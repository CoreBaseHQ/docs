CoreMCP ships as a single static Go binary. Three install paths, pick whichever fits.

## One-line install (recommended)

```bash
curl -fsSL https://get.corebasehq.com | sh
```

The script detects your OS + architecture, downloads the matching binary from [GitHub Releases](https://github.com/corebasehq/coremcp/releases), verifies the SHA256 against the published `checksums.txt`, installs to `/usr/local/bin` (or `~/.local/bin` if not root), and adds it to your shell `PATH` (`bash`, `zsh`, `fish`).

Environment overrides:

| Variable | Default | Purpose |
|---|---|---|
| `VERSION` | `latest` | Pin a specific release, e.g. `VERSION=v0.4.6` |
| `INSTALL_DIR` | `/usr/local/bin` or `~/.local/bin` | Force a target directory |

Verify after install:

```bash
coremcp --help
```

## Docker

Multi-arch image (`linux/amd64` + `linux/arm64`) published on each release tag.

```bash
docker pull y11t0/coremcp:latest

docker run --rm \
  -v "$(pwd)/coremcp.yaml:/app/coremcp.yaml:ro" \
  y11t0/coremcp:latest
```

For a persistent service, use the [`docker-compose.yml`](https://github.com/corebasehq/coremcp/blob/main/docker-compose.yml) shipped in the repo:

```bash
git clone https://github.com/corebasehq/coremcp.git
cd coremcp
cp coremcp.example.yaml coremcp.yaml   # edit DSN
docker compose up -d
```

The compose file pulls `y11t0/coremcp:latest` and mounts your local `coremcp.yaml` read-only.

For a full dev stack with MSSQL bundled, use [`docker-compose.dev.yml`](https://github.com/corebasehq/coremcp/blob/main/docker-compose.dev.yml):

```bash
docker compose -f docker-compose.dev.yml up --build
```

## From source

Requires Go 1.25.6 or newer:

```bash
git clone https://github.com/corebasehq/coremcp.git
cd coremcp
go build -o coremcp ./cmd/coremcp
sudo install -m 0755 coremcp /usr/local/bin/coremcp
```

Or via `make`:

```bash
make build && sudo make install
```

## Configure

Create `coremcp.yaml` next to the binary (or pass `--config /path/to/coremcp.yaml`):

```yaml
server:
  name: "coremcp-agent"
  version: "0.4.6"
  transport: "stdio"   # stdio (Claude Desktop, Cursor) | http (remote clients)
  port: 8080           # only used when transport=http

logging:
  level: "info"        # debug | info | warn | error
  format: "json"       # text | json

sources:
  - name: "erp_prod"
    type: "mssql"
    dsn: "sqlserver://core_ro:password@10.0.0.5:1433?database=ERP&encrypt=disable"
    readonly: true     # default — strongly recommended
```

Use a database user with `SELECT`-only grants. `readonly: true` is the default; setting it `false` enables `execute_procedure` for stored procs.

See [Configuration reference](/coremcp/configuration) for every option.

## Run

```bash
coremcp serve --config ./coremcp.yaml
```

The default `coremcp` command requires a subcommand; `serve` starts the MCP server. The agent registers with its configured transport — stdio mode reads/writes from stdin/stdout (used by MCP clients launching it directly), http mode listens on `:8080`.

For Claude Desktop, Cursor, or Continue config snippets, see [MCP clients](/coremcp/clients).

## systemd (Linux daemon)

For a long-running HTTP-transport agent on Linux:

```ini
# /etc/systemd/system/coremcp.service
[Unit]
Description=CoreMCP agent
After=network.target

[Service]
Type=simple
User=coremcp
ExecStart=/usr/local/bin/coremcp serve --config /etc/coremcp/coremcp.yaml
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now coremcp
sudo journalctl -u coremcp -f
```

Lock down the config: `chown root:coremcp /etc/coremcp/coremcp.yaml && chmod 0640 /etc/coremcp/coremcp.yaml`.

## Air-gapped

For environments without internet:

1. Download the release binary on a connected machine, copy it to the air-gapped host.
2. Database drivers are embedded in the binary — no further downloads needed.
3. Ship `coremcp.yaml` separately, never in version control.

For the full air-gapped CoreBase stack (panel + agent + LLM together, zero outbound network), contact sales for the Enterprise Container bundle.

## Upgrading

Re-run the install script or pull the latest Docker image — both overwrite the existing binary. The MCP protocol is versioned: a stale agent stays compatible with current CoreBase for at least 6 months.

```bash
# CLI
curl -fsSL https://get.corebasehq.com | sh

# Docker
docker pull y11t0/coremcp:latest && docker compose up -d
```

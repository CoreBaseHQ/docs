CoreBase gives you four ways to connect data to the agent, each with a different perimeter. The strictest mode keeps every row physically inside your network; the lightest pastes a DSN into our panel. Pick the one that matches your compliance posture.

## The four deployment modes

In every mode, anything CoreBase persists is **encrypted per tenant** and isolated at the database — see the [storage table](#whats-stored-on-the-orchestrator-any-deployment-with-a-cloud-control-plane) below.

## What CoreBase sees — by deployment mode

### Cloud-direct

When you paste a DSN into the panel:

| Direction | Payload |
|---|---|
| Cloud → Database | Read-only SQL queries opened directly from CoreBase Cloud |
| Database → Cloud | Result rows, returned to the agent and forwarded to the LLM |

The connection is opened from our infrastructure using credentials you provide. CoreBase enforces read-only at the session level — the database itself refuses mutating SQL, no parser hack required. Credentials are encrypted per tenant before being stored.

This is the fastest path. Use it when your buyer accepts "another SaaS vendor with database access" as part of their compliance model — the same posture you'd accept for any analytics or BI tool you've already onboarded.

### Cloud-relay (CoreMCP-based)

When the orchestrator is CoreBase Cloud and a CoreMCP agent runs in your perimeter:

| Direction | Payload |
|---|---|
| Cloud → Agent | Schema-discovery requests, SQL statements, natural-language prompts |
| Agent → Cloud | Schema metadata, **query result rows**, and the model's final answer |

Database credentials live on the CoreMCP agent and never reach our cloud. Connections originate inside your network. Rows still traverse the wire over TLS 1.2+ to reach the LLM. Anything CoreBase persists is encrypted per tenant.

Use this mode when credentials staying on-prem is a hard requirement but rows in transit (under TLS) are acceptable.

### Self-hosted

When you deploy the CoreBase Cloud component inside your own VPC:

- Same protocol, same code
- Rows stay inside your VPC — they reach your CoreBase pods, not ours
- LLM call still goes to whichever provider you configure; for a fully internal model, point CoreBase at a self-hosted vLLM / Ollama / Together endpoint

### Air-gap (Enterprise Container)

The strictest mode:

- The entire stack — CoreMCP + CoreBase + a local LLM (Llama 3, Mistral, your choice) — runs inside your perimeter
- Outbound network can be fully blocked
- **Raw rows physically cannot leave** — there is no remote endpoint to send them to

For regulated industries — defense, healthcare, banking. Contact sales for the Enterprise Container bundle.

## What's stored on the orchestrator (any deployment with a cloud control plane)

| Data | Encryption | Cross-tenant access |
|---|---|---|
| Schema metadata | Per-tenant key, encrypted at rest | Sealed at the database |
| Chat transcripts (prompts + answers) | Per-tenant key, encrypted at rest | Sealed at the database |
| Audit log (who asked what, which policies fired) | Per-tenant key, encrypted at rest | Sealed at the database |
| Corporate Memory (annotations + glossary) | Per-tenant key, encrypted at rest | Sealed at the database |
| Database credentials (cloud-direct mode) | Per-tenant key, encrypted at rest | Sealed at the database |
| Database credentials (cloud-relay / self-host / air-gap) | — | Stored on CoreMCP, never on the orchestrator |

## Compliance posture summary

| Mode | GDPR / KVKK | HIPAA / PCI | Sovereignty |
|---|---|---|---|
| **Cloud-direct** | DPA + EU region option | Same posture as any cloud BI tool | Best-effort |
| **Cloud-relay** | DPA + EU region option | Possible with BAA — contact us | Credentials on-prem |
| **Self-hosted** | Your tenancy, your jurisdiction | You hold all keys | Full |
| **Air-gap** | Zero external footprint | Suitable for restricted networks | Absolute |

## Verifying it yourself

CoreMCP is open source. Read the [MCP request handlers](https://github.com/corebasehq/coremcp/tree/main/pkg) — query execution is bounded to a small surface and `readonly: true` is the default on every source.

For CoreBase Cloud, the encryption pipeline derives a per-tenant AES-GCM key from a master key and applies it to every persisted field with sensitive content. The cloud control plane is closed source; security architecture details are available under NDA — contact us if you're evaluating for regulated use.

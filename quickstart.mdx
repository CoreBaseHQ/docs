The fastest path: sign in, add a source, build an agent. The on-prem CoreMCP path (for databases without an API, or ones behind a firewall) follows.

## Build an agent in the cloud

<Steps>
  <Step title="Sign in and add an LLM key">
    Create an org at [corebasehq.com](https://corebasehq.com). CoreBase is **bring-your-own-key** — in **Settings → LLM keys**, paste an Anthropic, OpenAI, Gemini, Groq, Mistral, Azure, OpenRouter, or Ollama key. Agents won't run without one. See [LLM keys](/platform/llm-keys).
  </Step>
  <Step title="Connect a source">
    In **Sources**, add what your agent will work on:

    - **Database** — paste a PostgreSQL DSN (cloud-direct), or register a [CoreMCP](/coremcp/intro) agent for SQL Server / Firebird.
    - **API** — give a REST OpenAPI URL or a GraphQL endpoint.
    - **SaaS app** — connect Jira, Gmail, GitHub, and 50+ more via OAuth. See [Connectors](/connect/connectors).

    Everything connects **read-only by default**. See [Connect your data](/connect/sources).
  </Step>
  <Step title="Ask, or build a flow">
    Open **Chat** and ask a question to confirm the source works:

    > How many customers signed up last month and what's the average order value?

    Then go to **Agents** and build a flow: drop a **trigger**, an **agent** step with an instruction and the source you just added, connect them, and hit **Run**. See [Agent platform](/agents/overview).
  </Step>
  <Step title="Make it proactive">
    On the trigger node, switch from **Manual** to **On a schedule** (e.g. daily at 09:00) or **When an event happens** (e.g. new Slack message). Now the agent runs itself. See [Triggers](/agents/triggers).
  </Step>
</Steps>

## Reach a database without an API, or one behind a firewall (CoreMCP)

For SQL Server, Firebird, or any database behind a firewall, run the open-source CoreMCP agent inside your network. It holds the credentials, runs queries locally, and dials outbound only.

<Steps>
  <Step title="Install CoreMCP">
    ```bash
    curl -fsSL https://get.corebasehq.com | sh
    ```

    Prefer Docker? `docker pull y11t0/coremcp:latest`. From source? `go build ./cmd/coremcp`. See [Install](/coremcp/install).
  </Step>
  <Step title="Configure a source">
    Create `coremcp.yaml` with a `SELECT`-only database user:

    ```yaml
    server:
      transport: http

    sources:
      - name: erp_prod
        type: mssql
        dsn: "sqlserver://core_ro:password@10.0.0.5:1433?database=ERP&encrypt=disable"
        readonly: true
    ```

    See [Connect a data source](/coremcp/connect) for `mssql`, `rest`, and `graphql` DSNs; full schema in [Configuration](/coremcp/configuration).
  </Step>
  <Step title="Connect it to CoreBase">
    In the panel, **Sources → Add agent**, register your CoreMCP agent. Its tables surface as a source your agents can use — same governance, same Unified Context.

    Working directly in Claude Desktop or Cursor instead? Point the client at the binary over stdio — see [MCP clients](/coremcp/clients). Raw rows stay on your network.
  </Step>
</Steps>

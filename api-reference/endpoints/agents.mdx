---
title: "Agents & runs"
description: "List agent flows, trigger governed runs, poll status, and decide approval gates."
---

Beyond chat, you can trigger your **agent flows** — multi-step, governed
automations that run durably on CoreBase's execution backend (read-only by
default, with approval gates and audit). Build flows visually in the panel, then
run them programmatically.

The flow runs under its project scope and the same governance as the panel —
the API can't bypass read-only/approval rules.

Every endpoint below accepts an optional **`project_id`** query parameter
(from `GET /api/v1/projects`); omit it to operate in your default
[project](/platform/projects).

## List agents

```http
GET /api/v1/agents?project_id=p1a2…&limit=100 HTTP/1.1
Host: api.corebasehq.com
Authorization: Bearer cb_live_xxx
```

Requires `mcp_query`. Paginated: pass `limit` (1–200, default 100) and the
previous page's `next_cursor` as `cursor`.

```json
{
  "data": [
    {
      "id": "a1b2…",
      "name": "Daily revenue digest",
      "status": "active",
      "is_enabled": true,
      "project_id": "p1a2…"
    }
  ],
  "next_cursor": null
}
```

| Field | Type | Description |
|---|---|---|
| `data[].id` | `string` | Flow id — use it to trigger a run |
| `data[].name` | `string` | Flow name |
| `data[].status` | `"draft" \| "active" \| "paused"` | Lifecycle status |
| `data[].is_enabled` | `boolean` | Whether triggers are enabled |
| `data[].project_id` | `string` | The project the flow belongs to |
| `next_cursor` | `string \| null` | Pass as `cursor` for the next page |

## Trigger a run

```http
POST /api/v1/agents/{flow_id}/run HTTP/1.1
Host: api.corebasehq.com
Authorization: Bearer cb_live_xxx
```

Requires the `agents_run` permission. Returns immediately — the run executes
asynchronously; poll `GET /api/v1/runs/{run_id}` for the result.

```json
{
  "run_id": "r9k2…",
  "workflow_id": "agentflow-r9k2…",
  "status": "running"
}
```

Only an **active, enabled** flow can be triggered — a draft, paused, or disabled
flow returns `409` (the API can't bypass the same availability rules as the panel).

| Status | Meaning |
|---|---|
| `403` | Token lacks `agents_run` permission |
| `404` | No agent flow with that id in the project |
| `409` | Flow isn't runnable (draft, paused, or disabled) |
| `503` | Agent execution unavailable |
| `502` | Run could not be started |

## Poll run status

```http
GET /api/v1/runs/{run_id} HTTP/1.1
Host: api.corebasehq.com
Authorization: Bearer cb_live_xxx
```

Requires the `agents_run` permission — run output, errors, and steps sit behind
the same boundary as triggering runs.

```json
{
  "id": "r9k2…",
  "flow_id": "a1b2…",
  "status": "succeeded",
  "trigger": "api",
  "output": "Revenue is up 12% week-over-week…",
  "error": null,
  "steps": [
    { "node_id": "agent-1", "label": "Summarize", "type": "agent", "status": "succeeded" }
  ],
  "started_at": "2026-06-23T12:00:00",
  "ended_at": "2026-06-23T12:00:14"
}
```

| Field | Type | Description |
|---|---|---|
| `status` | `"running" \| "awaiting_approval" \| "succeeded" \| "failed"` | Run state |
| `output` | `string \| null` | Final result text |
| `error` | `string \| null` | Failure reason, if any |
| `steps` | `array` | Per-node execution trace |
| `started_at` / `ended_at` | `string \| null` | ISO timestamps |

## Approve or reject a paused run

When a run hits an **approval gate**, its status becomes `awaiting_approval` and
it waits for a human decision. You can decide from the panel — or from the API,
so you can build the approval step into **your own** product's UI:

```http
POST /api/v1/runs/{run_id}/approve HTTP/1.1
Host: api.corebasehq.com
Authorization: Bearer cb_live_xxx
```

```http
POST /api/v1/runs/{run_id}/reject HTTP/1.1
Host: api.corebasehq.com
Authorization: Bearer cb_live_xxx
```

Both return `204 No Content`. **Approve** resumes the flow from where it paused;
**reject** ends it without taking the gated action. Requires the `agents_run`
permission.

| Status | Meaning |
|---|---|
| `404` | No run with that id in the project |
| `409` | Run isn't awaiting approval (already decided, finished, or still running) |
| `503` | Agent execution unavailable |

## End-to-end

```python
import time, httpx

H = {"Authorization": "Bearer cb_live_xxx"}
base = "https://api.corebasehq.com/api/v1"

run = httpx.post(f"{base}/agents/a1b2…/run", headers=H).json()
run_id = run["run_id"]

while True:
    r = httpx.get(f"{base}/runs/{run_id}", headers=H).json()
    if r["status"] == "awaiting_approval":
        # Your own approval logic/UI decides here:
        httpx.post(f"{base}/runs/{run_id}/approve", headers=H)
    elif r["status"] in ("succeeded", "failed"):
        print(r["status"], r.get("output") or r.get("error"))
        break
    time.sleep(2)
```

---
title: "POST /v1/chat/completions"
description: "OpenAI-compatible streaming chat completions."
---

The chat endpoint is OpenAI-compatible — point any OpenAI SDK at `https://api.corebasehq.com/v1` and it just works. Responses stream as `text/event-stream` using the standard `chat.completion.chunk` payload, terminated by `data: [DONE]`.

The model has access to your tenant's data sources, Corporate Memory, and audit policies — no extra setup per call.

<Note>
  `POST /v1/chat/completions` is the canonical path. The legacy `POST /v1/chat` is kept as an alias for backward compatibility and behaves identically.
</Note>

## Request

```http
POST /v1/chat/completions HTTP/1.1
Host: api.corebasehq.com
Authorization: Bearer cb_live_xxx
Content-Type: application/json

{
  "model": "corebase",
  "messages": [
    { "role": "user", "content": "How many active customers last month?" }
  ],
  "stream": true
}
```

### Body

| Field | Type | Required | Description |
|---|---|---|---|
| `messages` | `Array<{role, content}>` | yes | Full conversation history. 1–200 items. |
| `messages[].role` | `"user" \| "assistant" \| "system"` | yes | OpenAI-style role |
| `messages[].content` | `string` (1–8000 chars) | yes | Message text |
| `model` | `string` | no | Accepted but ignored — the actual model is the default LLM provider configured in your panel. |
| `stream` | `boolean` | no | Must be `true`. Non-streaming responses are not supported. Defaults to `true`. |

<Note>
  The endpoint is **stateless** — there's no server-side `chat_id`. Pass the full history on every call.
</Note>

## Response

`Content-Type: text/event-stream`. Each frame is a standard OpenAI `chat.completion.chunk`:

```
data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1716284400,"model":"anthropic/claude-3-5-sonnet-20241022","choices":[{"index":0,"delta":{"role":"assistant","content":""},"finish_reason":null}]}

data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1716284400,"model":"anthropic/claude-3-5-sonnet-20241022","choices":[{"index":0,"delta":{"content":"Top "},"finish_reason":null}]}

data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1716284400,"model":"anthropic/claude-3-5-sonnet-20241022","choices":[{"index":0,"delta":{"content":"customers"},"finish_reason":null}]}

...

data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1716284400,"model":"anthropic/claude-3-5-sonnet-20241022","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
```

## Using the OpenAI SDK

Because the wire format matches OpenAI, you can use any OpenAI client:

```python
from openai import OpenAI

client = OpenAI(
    api_key="cb_live_xxx",
    base_url="https://api.corebasehq.com/v1",
)

stream = client.chat.completions.create(
    model="corebase",
    messages=[{"role": "user", "content": "Top 3 customers by revenue this quarter?"}],
    stream=True,
)

for chunk in stream:
    delta = chunk.choices[0].delta
    if delta.content:
        print(delta.content, end="", flush=True)
```

```ts
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.CB_LIVE!,
  baseURL: "https://api.corebasehq.com/v1",
});

const stream = await client.chat.completions.create({
  model: "corebase",
  messages: [{ role: "user", content: "Top 3 customers by revenue this quarter?" }],
  stream: true,
});

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0].delta.content ?? "");
}
```

## Tool calls

When the model invokes one of your connected data sources, the call streams as a standard OpenAI `tool_calls` delta:

```json
{
  "choices": [{
    "index": 0,
    "delta": {
      "tool_calls": [{
        "index": 0,
        "id": "call_abc",
        "type": "function",
        "function": {
          "name": "erp_prod__execute_query",
          "arguments": "{\"sql\":\"SELECT TOP 3 ...\"}"
        }
      }]
    },
    "finish_reason": null
  }]
}
```

Tool execution happens server-side inside CoreBase — you don't need to handle the call. The next text deltas after the tool call carry the model's interpretation of the result.

## Curl example

```bash
curl -N -X POST https://api.corebasehq.com/v1/chat/completions \
  -H "Authorization: Bearer cb_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "corebase",
    "messages": [{"role": "user", "content": "Top 3 customers by revenue this quarter?"}],
    "stream": true
  }'
```

## Errors

| Status | Meaning |
|---|---|
| `400` | Body schema invalid, or `stream: false` requested |
| `401` | Missing or invalid token — see [Authentication](/api-reference/authentication#errors) |
| `403` | Token lacks `mcp_query` permission |
| `409` | No LLM provider key configured for the organization — set one in [Settings → LLM keys](/platform/llm-keys) |
| `429` | Rate limit hit. Honor `Retry-After`. |
| `503` | Transient backend issue — retry with exponential backoff |

## Multi-turn

Append assistant replies to the `messages` array on subsequent calls. The model uses the full conversation as context.

```jsonc
{
  "model": "corebase",
  "messages": [
    { "role": "user", "content": "Top customers this quarter?" },
    { "role": "assistant", "content": "Acme, Globex, Initech." },
    { "role": "user", "content": "And how do they compare to last quarter?" }
  ],
  "stream": true
}
```

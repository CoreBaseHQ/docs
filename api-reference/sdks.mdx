## Today: any OpenAI SDK

The Developer API speaks the OpenAI Chat Completions wire format, so you don't wait on an official CoreBase SDK — point your existing OpenAI client at CoreBase's base URL and it works.

<CodeGroup>

```python Python
from openai import OpenAI

client = OpenAI(api_key="cb_live_xxx", base_url="https://api.corebasehq.com/api/v1")

stream = client.chat.completions.create(
    model="corebase",
    messages=[{"role": "user", "content": "How many active customers last month?"}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)
```

```ts Node / TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.COREBASE_API_KEY,
  baseURL: "https://api.corebasehq.com/api/v1",
});

const stream = await client.chat.completions.create({
  model: "corebase",
  stream: true,
  messages: [{ role: "user", content: "How many active customers last month?" }],
});

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}
```

</CodeGroup>

Any language with an OpenAI client works the same way — Go, Ruby, Java, PHP — just swap in that language's official or community OpenAI SDK and point `base_url` / `baseURL` at CoreBase. See [Developer API](/api-reference/introduction) for the full endpoint reference and [Authentication](/api-reference/authentication) for how `cb_live_` tokens work.

## Official SDKs

Typed Node (TypeScript) and Python SDKs, purpose-built for CoreBase: typed
request/response shapes, streaming handled for you, CoreBase-specific error
types (rate limits, missing LLM key) instead of generic OpenAI ones, and a
one-call widget session token helper. PHP follows.

<Note>
  Publishing to npm and PyPI is in progress. Until they land, use the
  OpenAI-compatible path above (zero wait) — switching later is a drop-in
  change (same base URL, same auth). The method names and helper below are the
  real, generated surface.
</Note>

### Make a call

Authenticate with a `cb_live_` token (create one in the panel under **API
Tokens**), then call any operation. Methods are grouped by resource —
`chats`, `sources`, `agents`, `accounts`:

<CodeGroup>

```ts Node
import { Corebase } from "@corebasehq/node";

const corebase = new Corebase({
  bearerAuth: process.env.COREBASE_BEARER_AUTH ?? "",
});

// OpenAI-compatible chat over your connected data
const result = await corebase.chats.createCompletion({
  messages: [{ role: "user", content: "Which invoices are overdue?" }],
  stream: true,
});
console.log(result);

// List the sources the agent can reach
const sources = await corebase.sources.list();
```

```python Python
import os
from corebasehq import Corebase

with Corebase(bearer_auth=os.getenv("COREBASE_BEARER_AUTH", "")) as corebase:
    # OpenAI-compatible chat over your connected data
    result = corebase.chat.create_chat_completion(
        messages=[{"role": "user", "content": "Which invoices are overdue?"}],
        stream=True,
    )
    print(result)

    # List the sources the agent can reach
    sources = corebase.sources.list_sources()
```

</CodeGroup>

The client reads its token from the `COREBASE_BEARER_AUTH` environment variable
by default. Full method-by-method docs (agents, runs, plan, usage) live in each
SDK's repository README.

### Widget session tokens

Both SDKs ship a helper that signs a [widget JWT](/platform/widget#generating-the-jwt-server-side)
for one end-user — the right claim names, a required expiry, per-end-user
limits, and it never lets a passthrough claim overwrite `sub` or `exp`. Server
side only; the secret never reaches a browser.

<CodeGroup>

```ts Node
import { createWidgetToken } from "@corebasehq/node";

const token = await createWidgetToken(
  process.env.COREBASE_WIDGET_SECRET,
  user.id,                              // sub — shows in audit logs
  {
    expiresIn: 1800,                    // seconds; default 30 minutes
    sourceIds: ["orders", "invoices"],  // narrow within the widget's sources
    limits: { daily: 50, perMinute: 5 },
    claims: { branch: user.branch },    // for {{claim.branch}} headers
  },
);
```

```python Python
import os
from corebasehq import create_widget_token

token = create_widget_token(
    os.environ["COREBASE_WIDGET_SECRET"],
    user.id,                            # sub — shows in audit logs
    expires_in=1800,                    # seconds; default 30 minutes
    source_ids=["orders", "invoices"],  # narrow within the widget's sources
    daily_limit=50,
    per_minute_limit=5,
    claims={"branch": user.branch},     # for {{claim.branch}} headers
)
```

</CodeGroup>

The Node helper is async and runs on Node 18+, Deno, Bun, and edge runtimes
(WebCrypto, no Node-only APIs); the Python helper is standard-library only.

## Also today: the embeddable widget

If what you actually want is a chat UI inside your own product rather than a raw API client, you don't need either of the above — [`@corebasehq/widget`](/platform/widget) is a published, drop-in Preact component with its own JWT-based auth.

| | OpenAI SDK | `@corebasehq/widget` | Official SDKs (Node / Python) |
|---|---|---|---|
| Availability | Works today | Published | Rolling out now |
| Use case | Your backend calls CoreBase directly | Chat UI embedded in your product | Typed backend client + widget token helper |
| Auth | `cb_live_` token | Server-signed JWT | `cb_live_` token (client) / B2B secret (token helper) |

CoreBase connects to 50+ SaaS apps — Jira, Gmail, GitHub, Notion, Stripe, HubSpot, Zendesk, Linear, Asana, and more — through **managed OAuth**. You don't write an integration per app; you click connect, authorize, and the app becomes a source your agents can use.

## How it works

Authentication runs through **Nango** (a managed OAuth layer): the OAuth tokens live there, not in CoreBase, and calls go through an authenticated proxy that injects and refreshes them. To your agents, a connected app behaves like any other API source — the same governance applies.

<Note>
  SaaS connectors are a **cloud-relay** tier: auth and proxied calls pass through the connector cloud. This is distinct from the **sovereign** path for legacy/on-prem databases via [CoreMCP](/coremcp/intro), where data never egresses. Pick the tier that matches your compliance needs.
</Note>

## Connect an app

In **Panel → Sources → Add integration**, native sources (Slack, Microsoft 365) and SaaS apps appear in **one unified grid**. Pick an app, complete the OAuth flow, and it's connected — tools enabled by default.

## Action on every app

Every connected app can **take action**, not just feed retrieval:

- **Typed tools** — when the provider ships an OpenAPI spec, each operation becomes a precise, typed tool.
- **Generic request tool** — when it doesn't, CoreBase exposes a single governed `request` tool: the agent provides a method and path, and the call goes through the authenticated proxy. (LLMs already know the common SaaS API shapes.)

Either way the agent can do real work in the app — open a Jira issue, send a Gmail draft, post to a channel — subject to governance.

## Governance carries over

Connectors inherit the same controls as any source:

- **Read-only by default.** The generic tool only exposes `GET` until you enable writes; with writes on, all methods are allowed. Mutating operations are never handed to the agent on a read-only connection.
- **Source scoping.** An agent only sees the connectors you scope it to.
- **Per-tenant isolation & audit.** Same as everything else.

See [Governance](/concepts/governance).

## Events

Connected apps can also **trigger agents**. A new Jira issue, a new Gmail message, a Stripe payment — these surface in the [trigger event picker](/agents/triggers) and can wake a flow. Native Slack messages do too.

<Note>
  **Tools** (taking action) are live today. **RAG ingestion** — syncing an app's content into [Unified Context](/concepts/corporate-memory) for retrieval — is on the roadmap; you can enable it per connection ahead of the ingestion pipeline landing.
</Note>

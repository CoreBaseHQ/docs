CoreBase connects AI agents to the databases nobody else can reach. The old SQL Server behind a firewall, the Firebird file under a Delphi ERP, the air-gapped network an auditor won't let you open — CoreBase reaches them over the [Model Context Protocol](https://modelcontextprotocol.io), keeps queries read-only, and never moves raw rows out of your perimeter unless you choose to.

## The 60-second tour

Run the agent inside your network:

```bash
curl -fsSL https://get.corebasehq.com | sh

cat > coremcp.yaml <<EOF
sources:
  - name: erp
    type: mssql
    dsn: "sqlserver://core_ro:pass@10.0.0.5:1433?database=ERP&encrypt=disable"
    readonly: true
EOF
```

Or call CoreBase from your own apps with an OpenAI-compatible endpoint:

```bash
# 1. Get a CoreBase API token (Settings → Developer)
export COREBASE_API_KEY=cb_live_a1b2c3...

# 2. Add your own LLM provider key in the panel
#    (Settings → LLM keys → paste Anthropic/OpenAI/Gemini key)

# 3. Ask — OpenAI-compatible streaming response
curl -N -X POST https://api.corebasehq.com/v1/chat/completions \
  -H "Authorization: Bearer $COREBASE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "corebase",
    "messages": [{"role":"user","content":"Top 5 customers by revenue this quarter?"}],
    "stream": true
  }'
```

## What CoreBase is for

<CardGroup cols={2}>
  <Card title="The drivers nobody else ships" icon="database" href="/coremcp/intro">
    SQL Server 2000+ with Turkish_CI_AS collation. Firebird for Delphi-era ERPs (in active development). CoreBase speaks to the old guard other tools refuse to touch.
  </Card>
  <Card title="Reaches behind the firewall" icon="server" href="/concepts/zero-raw-data-egress">
    Cloud-direct (paste a DSN) · Cloud-relay (CoreMCP on-prem, outbound only) · Self-hosted (your VPC) · Air-gap (Enterprise Container). Pick the egress posture your compliance needs.
  </Card>
  <Card title="Query Memory" icon="brain" href="/concepts/corporate-memory">
    Schema annotations + business glossary tell the agent that `flag_2_new` means "cancellation flag, 1 = Active, 0 = Cancelled" and that `MRR` is computed from active subscriptions. It learns your data model without touching raw rows.
  </Card>
  <Card title="Isolated per tenant" icon="shield-check">
    Every tenant stays in its own sealed bubble — encrypted with its own key, read-only at the database, audited end-to-end with PostgreSQL Row Level Security.
  </Card>
</CardGroup>
